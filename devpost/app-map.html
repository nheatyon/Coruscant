One question.
Connected, saved records.

StarSearch helps interpret an Earth-observation need. Mission Control carries the same request through commercial decisions and supplied results. SatSuite connects permitted material and an authored finding back to the original question.

This is an offline reference map, not another screen in the app or a build checklist. Its source links open local files. They name stable symbols to search for; no interactive tour or extra exercise is assumed.

The connected system

01 / visible action → durable fact
  1. 01 / STARSEARCHQuestion, evidence, area

    Local interpretation, cited real or labeled demonstration catalog, deliberate circle and independent timing.

  2. 02 / EXPLICIT REVIEWPlanning or staff submission

    A tentative technical plan is optional. Saving Planning does not request staff review; submission is a separate action.

  3. 03 / FASTIFYCurrent authority first

    Server checks context, membership and permissions, then recovers an identical committed receipt or validates a new action.

  4. 04 / SQLITECommit the whole change

    Request/version, related records, history and action receipt commit together. Failure rolls them back together.

  5. 05 / MISSION CONTROLQuote → decision → schedule

    Private preparation, published offer, authorized acceptance and one recorded initial schedule remain separate decisions.

  6. 06 / SATSUITEReviewed, entitled result

    Exact-version publication plus separate access protects the pair/finding. Manual delivery records readiness; own points retain image identity.

React/TypeScript and Three.js run in the browser. One loopback Fastify process serves both the interface and JSON API. Node's SQLite adapter and private local files retain the records; external services are limited to explicit public-source acquisition and optional phrase-only place lookup.

A three-stop reference route

02 / quote acceptance

The build's restart exploration and acceptance-panel correction exposed two different obligations: a decision must persist once, and the interface must clearly finish that decision. These are useful stops when changing an agent-built workflow.

  1. Visible intent and completion

    client/features/workflow/QuoteCard.tsx · search QuoteDecision.

    The customer reviews the exact offer and selected-plan snapshot. After confirmed success, the callback clears the local form and closes the panel. An uncertain response keeps the original recovery action.

  2. Authority and one atomic decision

    server/workflow.ts · search executeWorkflow and acceptQuote.

    Current authority precedes receipt lookup. For a new decision, exact versions and the reviewed quote must still match; mutation, immutable acceptance and its receipt share a synchronous transaction.

  3. Evidence that distinguishes success from appearance

    tests/api/workflow.test.ts · search lost acceptance response.

    The check drops the response after a real commit, advances expiry and retries unchanged. It expects the original decision, rather than another acceptance. The related OS-process persistence check reopens exact plan/manifest/receipt lineage after restart.

A practice to reuse

State the observable result, find its commit boundary, then check a failure that could make the screen misleading. “Saved” is stronger when the same record survives restart; “completed” also needs the correct return and panel state. Use the quote behavior, the code above and the recorded checkpoint evidence together. This route is available for reference; it is not a new required exercise.

Records, transitions and gates

03 / no implied promotion

Planning → Submitted → In review ↔ Needs information → Quote ready → Accepted → Scheduled → Delivered

What survives

One request, several version histories
The request/reference stays the same. Aggregate version detects concurrent changes; brief revision identifies immutable requirements/contact/evidence snapshots. A same-input plan choice appends a plan version without rewriting priced terms.
Commercial records
Staff quote drafts remain private. Publication exposes exact terms; decline returns the request to In review. Acceptance freezes the quote, brief and selected plan or explicit None. Staff records one initial schedule against accepted work.
Material and findings
Image metadata versions, exact reviews, publication and organization entitlement are separate records. Finding review binds its cited pair. Changed review inputs invalidate the applicable approval; publication does not itself grant customer access.
Delivery and observations
A new delivery requires aligned supplied/requested dates, readable published pair and finding, active access, rights and actual private-file proof. The saved note is tied to its exact image/version and author; editing or deleting it cannot move that association.

Who may do it

Explicit simulation, real server guards
Fixed customer personas and separate Staff Admin entry use opaque server sessions. Current workspace membership, audience, context generation/token and CSRF checks decide each private action; knowing a record ID grants nothing.
Customer roles
Owner/Requester may write within permitted workspaces; Viewer reads. Offer acceptance/decline also requires the current Owner's organization-specific offer-selection grant. Customers can change only their own point observations.
Current permission after waiting
Protected bytes and saved-manifest reads check current authority before and after awaited file access. Browser context covers remove stale private views and revoke image Blob URLs; raw drafts stay scoped in tab memory.
Uncertain is not a new action
The unchanged retry keeps its command ID and payload. Authorized receipt recovery precedes new-action expiry/readiness tests, including after failed file preflight. Revoked authority still refuses a receipt.

Real discovery and technical planning

04 / evidence, not taskability

Current source → bounded calculation

The full adopted SAR + Earth Resources snapshot supplies exact catalog identities and orbital records. Independently cited instrument/mode/band facts stay separate from group membership and orbital geometry. Missing evidence remains unknown; pixel spacing is not native resolution.

The globe uses a shared paused UTC, at most 200 positions and 50 paths. The server's bounded plan calculation checks sampled center-point LOS, applicable idealized nominal-center corridor and solar constraints. Selected, shortlisted, Follow and applied area remain independent.

repository.ts → calculateAssessment → fixedChecks / instantaneousChecks

Explicit choice → immutable evidence

Automatic assessment does not save or submit. Edited instants get fresh checks; known required failures block a choice, and exact named unknowns require acknowledgement. Thermal nighttime policy and partial interval coverage remain unresolved where applicable.

A deliberate save retains one plan version and a private immutable manifest/digest. Live attachment references expire after 15 minutes; saved evidence instead uses current request permissions. A same-tab public handoff crosses only its guarded customer/workspace rotations. Restarted unfinished jobs become interrupted, while completed evidence persists.

prepareSelection / readSavedManifest → saveProposedPlan → insertProposedPlan / freezeAcceptedPlan

Model limits: WGS72 improved SGP4 with the stated Earth-frame approximation; 10-second samples and ≤1-second refinement of detected brackets can miss short events. Jobs stop at their execution/evaluation/output bounds and report incomplete coverage. A center-point opportunity or idealized corridor is not actual attitude, whole-area imageability, operator availability, booking, collection or a delivery promise.

Run it again

06 / one local origin

Existing workspace

Select Node 24.22.1 and npm 11.19.1. From the project root, npm start reopens an already built compatible installation.

source "$HOME/.nvm/nvm.sh"
nvm use 24.22.1
npm start

Open http://127.0.0.1:3000/ and keep that same origin. Before rebuilding an update, gracefully stop the actual listener; then use:

npm run build
npm run db:migrate
npm run demo:init
npm start

Ordered migration/init preserves D0 and saved work. SQLite, private material, manifests and signing key live under the ignored local data root. Do not delete it to fix an update. No real login, API key or .env credential is required.

Verification entry points

npm run verify:runtime
npm run check
npm run test:e2e

check runs type checks plus domain/API tests. test:e2e builds and runs Chromium/WebKit against an isolated temporary test root and port 3100; it does not use the ordinary workflow database.

npm run smoke:workspace is a read-only public/denial probe of the running installation. verify-clean-checkout.mjs checks a fresh Git snapshot separately. The canonical evidence record distinguishes actual passes, failed attempts, learner reports and open gates; generating this map passes none of them.

Full tests and acquisition can take time. The map itself performs no commands or network calls.

First-run order on a fresh checkout

Use the pinned runtime, then the exact order below. Initial dependencies/assets and installed Playwright browsers need network access; follow the README setup for runtime installation and browser prerequisites.

npm ci
npm run verify:runtime
npm run build:server
npm run assets:fetch
npm run db:migrate
npm run demo:init
npm run build:client
npm start

The local cached workflow works offline after setup. Fresh real orbital prediction still requires sufficiently fresh permitted cached elements. Source refresh and optional place lookup require their own deliberate network actions.

Demonstration limits: fixed personas simulate access, authored Earth tracks are synthetic, and the supplied SAR comparison pair is illustrative artwork. Real catalog records and predictions do not imply operator agreement. Visible/SWIR/Thermal and Single-observation planning do not supply those products; actual optical/single-observation fulfillment, payments and real tasking remain outside this release.
